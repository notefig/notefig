# Fork audit against spec 01 §5.1a

Audit of `crates/markdown-editor` (fork of wabzqem/gpui-kit-markdown-editor
0.1.1) against the checklist in `spec/01-editor.md` §5.1a, done before the
Notefig work. "Verdict" says what it means for Option A.

| Item | Finding | Verdict |
|---|---|---|
| **Position model** | A position is `BlockPosition { block: BlockId, offset, affinity }`; `offset` is a **UTF-8 byte offset** into the leaf's flat text, on a grapheme boundary. Atomic leaves (custom atoms, rules) use 0/1. Inline atoms (images, custom inline nodes) are one U+FFFC (3 bytes). The tree is a `HashMap<BlockId, BlockEntry>` with an order index; there are no integer document positions. | An exact PM mapping **is computable** by walking the tree: every container adds 2, a textblock adds its UTF-16 length + 2, an atom leaf adds 1, an inline atom (U+FFFC, 1 UTF-16 unit) matches PM's leaf size. Hard breaks are `\n` in the flat text: also 1 unit, as in PM. Differences: images are inline here (block in TipTap), frontmatter is document-level (we count it as a 1-size leaf at 0), table rows/cells and list items nest the same way. Implemented as `pm.rs` (O(n) per query; cache per revision if it shows up in profiles). |
| **Steps and mapping** | Four primitive invertible steps (`ReplaceText`, `ReplacePlain`, `InsertBlocks`, `RemoveBlocks`) plus `SetKind`; each returns its inverse and a `StepMap`. `Transaction::map_selection` maps a selection through one transaction's maps. There is no long-lived `Mapping` object, but `StepMap`s compose by folding, so ranges can be mapped across transactions by keeping the maps (what change tracking needs). Block ids are stable through edits, undo and redo, so decorations keyed on `(BlockId, range)` only need text maps. | Good enough. Added: transactions keep their maps (`Transaction::maps`), and the editor maps tracked ranges through every committed transaction (`tracking.rs`). |
| **Plugin hooks** | None in the PM sense. No `filterTransaction`, `appendTransaction`, decorations or plugin views. Input rules are a fixed enum (`InputRule`) with a host filter. A `normalize` pass ends every transaction (the closest thing to `appendTransaction`). Range backgrounds per leaf exist (used for selection), which is the decoration seam we reuse. | Missing, but the Notefig features we need can be done in the editor itself: range backgrounds for diff lines and search hits, paint-time quads for the change gutter, events for `/`. A general plugin API is post-MVP. |
| **Node views** | Custom block atoms (`BlockKindData::Custom` holding a `MarkdownNode`) render through gpui-kit's `MarkdownExtensions` block renderers. There is no editable content slot. | Added an app node-view callback for prompt widgets; the app's element hosts its own focused input entity (the draft lives outside the document, matching "draft not in the markdown"). An in-document `ContentSlot` is **not** implemented. |
| **Markdown** | Parse: gpui-kit's `parse_markdown` (markdown-rs mdast with GFM) into gpui-kit `BlockNode`s, then imported into the model. Serialize: its own canonical writer (`serialize.rs` + `markdown_source.rs`): flanking-aware marks, whitespace hoisting, escaping, `<mark>`/`<u>`. It is **not** byte-compatible with prosemirror-markdown (e.g. `<br>` for hard breaks, `---` delimiter rows, `\[` escapes), and the parser is markdown-rs, not markdown-it. Unknown HTML is kept as opaque source atoms (good); `<sub>`/`<sup>` were raw-tag atoms. | Instead of chasing byte parity with prosemirror-markdown, serialization is now **source-preserving**: untouched blocks write their original bytes, only edited blocks use the canonical writer. That makes open + save an identity on every file, which is the property §1.7 really protects (no churn, no git noise). |
| **Tables** | GFM tables with alignment, `BlockSelection::Cells` (cell selection), Tab/Shift-Tab, row/column insert/delete, grip menu with alignment. No column resize; always written as GFM pipes (cells hold one inline paragraph, so the HTML fallback never applies). | Above MVP needs. Column widths are not modelled (also lossy in TipTap). |
| **Virtualization / perf** | Top-level blocks (and chunks of long top-level lists) are culled outside 2 viewports of overscan; per-block revisions mean one keystroke re-projects one leaf (`long_document_reprojects_one_leaf_per_keystroke`). Nested long lists and long tables are laid out in full. Not measured on the 8k-line fixture in this pass. | Promising; the 8k-line SLO run is still to do. |
| **History** | `BlockUndoManager`: coalescing by intent (typing, backspace, word delete) until a caret move or blur; atomic otherwise; 1000 entries. No time-based `newGroupDelay`, no `addToHistory:false`, no rebasing over non-history steps (every transaction is history). | Adequate. External merges are ordinary atomic history entries, so ⌘Z undoes an agent write (spec §2.7). |
| **IME** | `EntityInputHandler` with marked text, UTF-16 ↔ byte conversion per leaf, composition grouped into one undo entry. Unverified on macOS by upstream (developed on Linux). | Keep; verify on macOS. |

Overall: the fork passes as a base. The two structural gaps are the missing
plugin/decoration layer and the lack of an editable slot inside node views;
both have MVP workarounds (see `docs/notefig.md`).
